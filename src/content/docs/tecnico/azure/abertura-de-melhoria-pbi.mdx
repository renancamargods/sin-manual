## Visão geral

Esta página traz um **modelo de prompt** para gerar a **documentação de requisito** de uma melhoria/desenvolvimento e o **passo a passo** para abrir o **PBI (Product Backlog Item)** no **Azure DevOps**, vinculado ao Pedido e com todos os **campos obrigatórios** preenchidos.

A ideia é sempre a mesma: **preencha o prompt → gere a documentação → cole o texto no campo "Description" do PBI → preencha os campos obrigatórios → salve.**

## Como usar (passo a passo)

1. Copie o modelo abaixo e **preencha o que está entre colchetes** com a sua funcionalidade.
2. Gere a documentação de requisito (com a IA/assistente).
3. No Azure DevOps, a partir do **Pedido**, adicione um **Link pai (Parent) do tipo Product Backlog Item**.
4. **Cole o texto gerado no campo "Description"** do PBI.
5. Preencha os **campos obrigatórios** (seção abaixo) e **salve**.

## Modelo do prompt

```text
Aja como um Product Owner (PO) / Analista de Requisitos sênior e escreva uma documentação de requisito de software detalhada, pronta para virar um PBI no Azure DevOps, para a funcionalidade abaixo.

Funcionalidade: [descreva brevemente o que precisa ser feito. Ex: botão de exportação de relatórios em PDF]
Objetivo do Negócio: [por que fazer / que problema resolve. Ex: permitir que gestores baixem dados para reuniões]
Público-Alvo: [quem vai usar. Ex: administradores do sistema]
Regras/Validações Principais: [Ex: apenas dados do mês atual, gerar em menos de 5 segundos, formato A4]

Entregue a documentação com:
- Título do PBI
- Descrição / Contexto
- Critérios de Aceite (lista verificável; use Dado-Quando-Então quando fizer sentido)
- Regras de Negócio e Validações
- Fora de Escopo (o que não será feito)
- Dependências / Impactos (telas, integrações, permissões afetadas)
- Observações Técnicas (se houver)
```

## Como abrir no Azure DevOps

O PBI é criado **a partir do Pedido**, como um item **pai** (o Pedido fica como filho do PBI):

## Campos obrigatórios do PBI

Preencha **todos** os campos abaixo antes de salvar (o Azure bloqueia o salvamento se faltar algum — ex.: *"Field 'Requesting User' cannot be empty"*):

<DocTable
  headers={['Campo', 'O que preencher']}
  rows={[
    ['State', 'O estado do item — ver a tabela "Estados (State)" logo abaixo.'],
    ['Area', 'Projetos Sin - Scrum.'],
    ['Iteration', 'Projetos Sin - Scrum.'],
    ['Description', 'A documentação de requisito gerada pelo prompt.'],
    ['Demand', 'A demanda relacionada.'],
    ['Request Date', 'A data da solicitação.'],
    ['Requesting User', 'O usuário que está solicitando.'],
    ['Ticket', 'Se houver ticket de suporte (Freshdesk/atendimento), o número do ticket; se não houver, o número da tarefa.'],
    ['Department', 'O departamento responsável.'],
    ['Board', 'O board/quadro de destino.'],
    ['Priority / Severity', 'Prioridade e severidade da melhoria (ex.: 3 - Medium).'],
  ]}
/>
