## Visão geral

O sistema versiona a **estrutura do banco de dados** com **migrations** do Entity Framework Core: cada mudança de estrutura (nova tabela, coluna, índice, remoção) é uma migration numerada, aplicada em ordem. Isso mantém o banco sincronizado com o código em todos os ambientes.

## Convenção de nome

Cada migration segue o padrão:

`&lt;timestamp&gt;_Migration_&lt;Autor&gt;_&lt;Descrição&gt;`

- **timestamp** — data/hora de criação (ex.: `20260827140919`), que também define a **ordem** de aplicação.
- **Autor** — quem criou (ex.: `LuanHora`, `LidiaBrito`, `WilliamPereira`).
- **Descrição** — o que a migration faz (ex.: `Entidade_ControleFuncionalidades`, `Melhorias_LogsExecucaoServicos`).

## Como são aplicadas

As migrations são aplicadas pela ferramenta do EF Core / pelo processo de deploy (não são aplicadas automaticamente na subida da aplicação). O par de arquivos de cada migration (a migration em si + o `.Designer`) e o `ModelSnapshot` do contexto mantêm o estado atual do modelo.

<Callout type="cuidado" title="Não editar migration já aplicada">
Uma migration que já rodou em algum ambiente **não deve ser alterada** — o correto é **criar uma nova** migration para o ajuste. Alterar uma migration antiga quebra o histórico e a sincronização entre ambientes.
</Callout>
