## Visão geral

Em **Homologação**, os pagamentos de cartão **não passam por captura real** na adquirente. Para o pedido avançar (ficar **"pago"**), é preciso **simular a confirmação manualmente**. O caminho muda conforme o gateway/forma de pagamento: **PagarMe**, **PayGo** ou **Pagamento Misto**.

<Callout type="cuidado" title="Só em Homologação">
Este procedimento é exclusivo de **HML/QA**. Nunca aplique em Produção — em Produção a confirmação vem da adquirente real.
</Callout>

## Antes de começar

- Acesso de **consulta ao banco** (para o SELECT que traz os dados do pagamento).
- O **pedido** já criado, com a cobrança/link gerado.

## Passo comum — pegar os dados no banco

Rode o **SELECT** abaixo para localizar os pagamentos do pedido (pelo **Sequencial**):

```sql
-- pagamento cartao misto
SELECT PagamentoMisto.DadosDoCartao, Pedido.Sequencial
FROM Pedidos_PedidoInformacaoDePagamentoMisto Pagamentomisto WITH (NOLOCK)
JOIN Pedidos_Pedido Pedido WITH (NOLOCK)
    ON Pedido.IdPedido = Pagamentomisto.IdPedido
WHERE Pedido.Sequencial IN ('2026XXXXXXX');
```

Campos que ele traz:

No pagamento misto o SELECT retorna **uma linha por pagamento**. A URL indica o gateway: `...pagar.me/...` é **PagarMe**; `...gate2all.com.br/...` é **PayGo**.

## Caso 1 — PagarMe (simular o webhook `charge.paid`)

Ajuste o retorno do webhook trocando os campos:

## Caso 2 — PayGo (gerador de cartão)

1. Pegue o **link** e abra a **URL (https)** que aparece nos dados do cartão no SELECT.
2. Abra um **gerador de cartão de crédito** e use **SEMPRE VISA**.

## Caso 3 — Pagamento Misto (validação via GraphQL)

A confirmação é feita pela **mutation**:

```graphql
mutation {
  pedidoInformacaoDePagamentoMisto {
    integrarPagamentosMistos {
      idPedido
    }
  }
}
```
