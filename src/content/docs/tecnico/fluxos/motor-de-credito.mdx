## Visão geral

O **Motor de Crédito** é a **análise automática de crédito do pedido**. Quando o pedido é **enviado para aprovação**, o motor aplica uma **sequência de regras** e decide, sem intervenção manual, se o pedido pode **seguir aprovado** ou se precisa ir para a **Mesa de Crédito** (análise humana).

Ele é diferente da [análise de crédito e antifraude (ClearSale)](/tecnico/fluxos/credito-e-antifraude-clearsale), que acontece no **cadastro do cliente**. Aqui a análise é **por pedido**.

## Antes do motor rodar: cliente apto

O motor só roda para pedidos que conseguem ser **enviados**. O envio exige que o **cliente esteja Ativo (apto)**. Se o cadastro estiver, por exemplo, em **"Negado Análise Crédito"**, o envio é **bloqueado** com aviso e o motor **não chega a rodar** — o cliente precisa estar no status **"Ativo"** primeiro.

## Como o motor decide

A análise é **sequencial** e **para na primeira regra que decide**. Se nenhuma regra decidir, o pedido é **Aprovado**.

Antes das regras, há duas checagens de entrada: se o **cliente não existe na base de análise** ou se a **condição de pagamento está vazia**, o pedido vai direto para a **Mesa de Crédito**.

<Callout type="info" title="Tolerância do CAR vencido">
No **CAR Vencido**, o pedido fica **dentro da tolerância** quando o atraso é pequeno, o valor vencido é baixo ou o perfil do cliente é favorável — todos **critérios configuráveis**. Fora desses critérios, o pedido vai para a **Mesa de Crédito**.
</Callout>
