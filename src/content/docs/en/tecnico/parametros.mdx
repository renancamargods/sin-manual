## Overview

Much of the system's behavior is adjusted by **configuration**, without touching the code. That configuration is stored as **parameters** — usually **per company** — which the modules read to decide rules and values.

<Callout type="cuidado" title="Broad impact">
Changes to parameters may affect **several modules at once** and often apply **per company**. Assess the impact before changing.
</Callout>

## How parameters are stored

- **Parameter** — a named configuration group, tied to a **company**. Each parameter holds one or more Key/Value pairs.
- **Key and Value** — the **`Key` → `Value`** pairs inside a parameter (also per company). This is where the actual settings live (the "Key and Value" screen edits these pairs).
- Every change is recorded in the parameter **log**.

## Default password-policy values

Some parameters have a **default value** defined in the system (the `Chaves` enum) — for example, the **password policy**: password validity, minimum length, number of previous passwords blocked, uppercase/lowercase/digit/special-character requirement, lockout minutes and max attempts. The values are in [Database → Value Mapping](/en/tecnico/banco-de-dados/de-para).

## Per-Lounge product parameters

Besides general configuration, there are **product-specific parameters per Lounge/branch** (which products are available and how they are routed). This is covered in the [Product Configuration in the Lounge](/en/tecnico/fluxos/configuracao-de-produtos-no-lounge) flow.
