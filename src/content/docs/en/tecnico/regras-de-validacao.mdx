## Overview

Each screen has **validation rules** that decide whether a record can be **saved/submitted**. They come from the code (FluentValidation, in the domain layer), so they **reflect the real behavior** — it is the same engine that blocks the button. This section documents those rules **per screen**, so support and QA know *why* a submission did not go through.

## When the rules fire

- On **"Save" / "Save and Continue"** and on **"Submit"** — validation runs at save/submit time.
- Some rules only apply in **certain contexts** (e.g., when **adding an item**, or only on **submission to the queues**).
- Many rules are **conditional** — they depend on:

<Callout type="info" title="Source of the rules">
The rules documented here come from the system **validators** (FluentValidation). Rules that are commented out/disabled in the code are **not** included.
</Callout>
