## Overview

The **Credit Engine** is the **automatic credit analysis of the order**. When the order is **submitted for approval**, the engine applies a **sequence of rules** and decides, with no manual action, whether the order can **move forward approved** or must go to the **Credit Desk** (human review).

It differs from the [credit and anti-fraud analysis (ClearSale)](/en/tecnico/fluxos/credito-e-antifraude-clearsale), which happens at the **customer registration**. Here the analysis is **per order**.

## Before the engine runs: eligible customer

The engine only runs for orders that can be **submitted**. Submission requires the **customer to be Active (eligible)**. If the registration is, for example, in **"Negado Análise Crédito"** (credit analysis denied), submission is **blocked** with a warning and the engine **does not run** — the customer must be in the **"Active"** status first.

## How the engine decides

The analysis is **sequential** and **stops at the first rule that decides**. If no rule decides, the order is **Approved**.

Before the rules, there are two entry checks: if the **customer does not exist in the analysis base** or the **payment term is empty**, the order goes straight to the **Credit Desk**.

<Callout type="info" title="Overdue receivables (CAR) tolerance">
For **Overdue Receivables**, the order is **within tolerance** when the delay is short, the overdue amount is low, or the customer profile is favorable — all **configurable criteria**. Outside those criteria, the order goes to the **Credit Desk**.
</Callout>
