## Overview

The **Loading List (Romaneio)** flow standardizes the shipment dispatch process of the S.I.N Implante System, from the initial setup of registrations to the creation, checking, collection and sending of the shipment. The goal is to ensure standardization across operators, shipment traceability and compliance with the company's quality criteria.

The flow goes through screens in the **Orders**, **Administrator** and **Invoicing** modules, and ends by sending the collected shipment to the **TMS** (external transportation management system).

## When to use this flow

- Prepare a shipment for dispatch, from picking to collection.
- Generate and print the volume labels of a shipment.
- Group shipments into a loading list and check their volumes.
- Record the collection and send the loading list to the TMS.

## How to access

The screens involved in this flow are:

- Orders → Carrier
- Administrator → Center (Lounge)
- Administrator → Label Printer
- Invoicing → Shipments Awaiting Picking Queue
- Invoicing → Label Generation Queue
- Invoicing → Loading List Queue

## Before you start

Before running the flow day to day, the registrations below must be configured.

### Carrier (Orders module)

In **Orders → Carrier**, the **"Available in Loading List?"** option must be set to **Yes** so the carrier appears in the selection during the shipment. This setting is what makes the carrier show up in the selection field, both in the Shipments Awaiting Picking Queue and at picking finalization.

### Center / Lounge (Administrator module)

In **Administrator → Center (Lounge)**, the **"Available for the Loading List Flow?"** option defines the lounge's path:

- **Yes** — the lounge starts appearing in the Shipments Awaiting Picking Queue, entering the loading list flow.
- **No** — the lounge follows the standard operational flow, without going through the loading list.

## Step by step

### 1. Shipments Awaiting Picking Queue

Invoicing module.

1. **Lounge identification** — when the screen opens, the system checks the shipment's origin lounge and applies the registration settings. If the lounge is enabled and the carrier is correctly configured, the **Carrier** field is shown.
2. **Scanning and saving** — the operator scans the shipment products and saves the information.
3. **Picking finalization** — clicking **"Send Order to Invoicing"** opens the **"Finalize Picking"** modal with two required fields: **Volumes** (number of shipment labels) and **Carrier**.
4. **Confirmation and sending to SAP** — the operator clicks **"Confirm and Send SAP"** (green button) and the system sends the shipment to invoicing.

<Callout type="info" title="How to fill in the finalization">
The **Carrier** field already comes filled with the order and SAP return information; change it only if needed. The **Volumes** field must be entered by the operator. When done, the system returns to the initial screen and shows the message **"Reading saved successfully"**.
</Callout>

<Callout type="atencao" title="Manual carrier selection">
The carrier is selected manually until the development change responsible for automatically importing SAP data into SIN SALES is completed.
</Callout>

### 2. Label Generation Queue

Invoicing module.

1. **Listing completed shipments** — the screen shows only shipments completed and sent to invoicing. By default, the **"With Carrier?"** and **"With Volume?"** filters are set to **Yes**.
2. **Opening the shipment** — the operator selects the shipment and clicks **"Edit"**, opening the "Shipment Label Generation" screen with the shipment, SAP order, customer, carrier and volume data.
3. **Generating and printing labels** — clicking **"Generate Labels"** runs the checkout and shows the labels, enabling the **Print** button (individual or **"Print All"**). On printing, the **"Select Printer"** popup opens with the registered printers.
4. **Sending to loading list** — after printing all labels, the **"Send to Loading List"** button is enabled. When triggered, the shipment leaves this queue and moves to the Loading List Queue.

<Callout type="atencao" title="Label printing">
When the system parameter **EnviarZplParaImpressora** is set to **false**, the system allows advancing without physically printing the labels. Otherwise, all labels must be printed to release the send to the loading list.
</Callout>

### 3. Loading List Queue

Invoicing module. The screen has two tabs: **Shipments Awaiting Loading List** and **Created Loading Lists**.

**"Shipments Awaiting Loading List" tab**

1. **Shipment selection** — select at least one available shipment and click **"Create Loading List"**.
2. **Loading list creation** — the system opens the "Create Loading List" screen with the selected shipments. After confirmation, the loading list appears in the **Created Loading Lists** tab with the initial status **In Checking**.

**"Created Loading Lists" tab — status cycle**

Each loading list goes through four statuses, each in a tab of the detail screen:

1. **In Checking** — initial status. You can edit or delete the loading list. Clicking **Edit**, the **"Volume Checking"** enables barcode scanning (**VOL-NNN-REMESSA** pattern). After checking all volumes, the **"Generate Document"** button is enabled.
2. **Checked** — clicking **"Generate Document"**, the loading list moves to the **Document** tab and opens the "Loading List Check" screen. Clicking **Print** generates the PDF; then **"View Document"** opens the document on screen, with a floating **Print** button to generate the PDF.
3. **Collection** — in the **Collection** tab, fill in the required data and click **"Confirm Collection"**. The status changes to **Collected**.
4. **Collected / Sent** — after confirming the collection, the flow sends the loading list to the TMS. Once sent, the final status becomes **Sent**, ending the shipment cycle.

<Callout type="info" title="Loading list listing filters">
The loading list listing offers filters to find a specific loading list: **Loading List No.**, **Date from** and **Date to** (creation period), **Loading List Status**, **Carrier** and **Lounge**.
</Callout>

<Callout type="info" title="The loading list document">
The document consolidates the shipment information: loading list identification (number and date), carrier, list of linked shipments and volumes, and collection data. The address shown always corresponds to the **origin Lounge address** of the shipment.
</Callout>

## Rules and cautions

- The Label Generation Queue only shows shipments with **carrier** and **volume** filled; without that data, the shipment does not appear.
- The **"Generate Document"** button only enables after scanning **100% of the volumes** of the shipment.
- Each volume's barcode must follow the **VOL-NNN-REMESSA** pattern; deviations prevent checking.
- The **"Send TMS"** button only appears after the shipment reaches the **Collected** status.
- Changes to the carrier or center/lounge settings take effect immediately on the operational screens; validate the impact before changing registrations in production.
