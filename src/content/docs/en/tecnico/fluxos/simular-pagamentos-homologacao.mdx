## Overview

In **Homologation**, card payments **do not go through real capture** at the acquirer. For the order to move forward (become **"paid"**), the confirmation must be **simulated manually**. The path changes according to the gateway/payment method: **PagarMe**, **PayGo** or **Mixed Payment**.

<Callout type="cuidado" title="Homologation only">
This procedure is exclusive to **HML/QA**. Never apply it in Production — in Production the confirmation comes from the real acquirer.
</Callout>

## Before you start

- **Read access to the database** (for the SELECT that returns the payment data).
- The **order** already created, with the charge/link generated.

## Common step — get the data from the database

Run the **SELECT** below to locate the order's payments (by **Sequencial**):

```sql
-- pagamento cartao misto
SELECT PagamentoMisto.DadosDoCartao, Pedido.Sequencial
FROM Pedidos_PedidoInformacaoDePagamentoMisto Pagamentomisto WITH (NOLOCK)
JOIN Pedidos_Pedido Pedido WITH (NOLOCK)
    ON Pedido.IdPedido = Pagamentomisto.IdPedido
WHERE Pedido.Sequencial IN ('2026XXXXXXX');
```

Fields it returns:

<DocTable
  headers={['Field', 'What it is']}
  rows={[
    ['Sequencial', 'Order sequential number (the WHERE filter).'],
    ['DadosDoCartao', 'JSON with the data of each payment on the order.'],
    ['DadosDoCartao → IdTransacao', 'Transaction id — used as code in the PagarMe webhook.'],
    ['DadosDoCartao → Url', 'Charge link (https) — the URL you open in the PayGo case.'],
  ]}
/>

For mixed payment the SELECT returns **one row per payment**. The URL tells the gateway: `...pagar.me/...` is **PagarMe**; `...gate2all.com.br/...` is **PayGo**.

## Case 1 — PagarMe (simulate the `charge.paid` webhook)

Adjust the webhook payload by replacing the fields:

<DocTable
  headers={['Field', 'Replace with']}
  rows={[
    ['amount', 'The payment amount.'],
    ['code', 'The generated transaction id.'],
    ['acquirer_auth_code', 'A random 6-digit number.'],
  ]}
/>

Example payload:

```json
{
  "id": "hook_TESTE_CONSIGNADO_592803",
  "type": "charge.paid",
  "account": { "id": "acc_XXXXXXXX", "name": "S.I.N. IMPLANT SYSTEM LTDA" },
  "data": {
    "id": "ch_TESTE_CONSIGNADO_592803",
    "amount": 5670,
    "paid_amount": 5670,
    "status": "paid",
    "order": { "id": "or_TESTE_CONSIGNADO_592803", "status": "paid", "code": "pl_XXXXXXXX" },
    "last_transaction": { "acquirer_auth_code": "159753", "status": "captured", "device_serial_number": null },
    "charges": [
      { "last_transaction": { "acquirer_auth_code": "159753", "status": "captured", "device_serial_number": null } }
    ]
  }
}
```

## Case 2 — PayGo (card generator)

1. Take the **link** and open the **URL (https)** shown in the card data from the SELECT.
2. Open a **credit card generator** and always use **VISA**.

## Case 3 — Mixed Payment (validation via GraphQL)

Confirmation is done through the **mutation**:

```graphql
mutation {
  pedidoInformacaoDePagamentoMisto {
    integrarPagamentosMistos {
      idPedido
    }
  }
}
```
