## Overview

The **Order Approval WITHOUT Ignition** flow describes, step by step, how an order is **created, sent and approved** through the **WITHOUT Ignition queue** — a faster, more direct path. The process has two parts: the **system preparation** (done once by the administrator) and the **day-to-day** (order creation and approval tracking).

The approval path follows exactly the configured **Approval Rule**. Some steps only apply depending on the order characteristics — for example, the **Collections – National** step only happens when the payment method is **PIX or Card**.

## When to use this flow

- Create a new order and send it for approval through the WITHOUT Ignition queue.
- Prepare the approval rule and steps used by this flow.
- Track the order through the approval steps until it is released.

## How to access

- Administrator module → Feature Control (preparation)
- Approvals module → Approval Rule (preparation)
- Orders module → Order (day-to-day use)

## Before you start

- Confirm with the administrator that the **approval rule** and the **steps** are already configured and active.
- Have the **customer** the order will be created for.
- Know the **payment method** of the order — it affects the National Collections step.

## Part 1 — System preparation (done by the administrator)

These steps are usually already configured. They only need to be done once.

### Step 1 — Set whether the queue uses Ignition

In the **Administrator** module, **Feature Control** screen, you can enable or disable the use of the Ignition queue. For this process, the option must be **ACTIVE so that the Ignition queue is NOT used** — the order follows the simplest path.

### Step 2 — Configure the Approval Rule

In the **Approvals** module, **Approval Rule** screen, define the **rule name**, the **approval entity** and the **execution mode**:

<DocTable
  headers={['Execution mode', 'What it means']}
  rows={[
    ['Parallel', 'There is no order between the approvers.'],
    ['Sequential', 'Approval follows the order registered in the steps.'],
  ]}
/>

### Step 3 — Register the approval steps

Within the rule, click **"New approval step"** (or edit an existing one). Configure the **responsible group** and the **order**, keeping the step **ACTIVE** so it works in the process.

## Part 2 — Order creation and sending (day-to-day use)

### Step 1 — New order

Access the **Orders** module, **Order** screen, and click **"+ New Order"**. Then **select the customer** for the order.

### Step 2 — Fill in the order data

Go to the **"Order Data"** tab and fill in the **required fields** (shown in **red**).

### Step 3 — Save and send for approval

Click **"Save and Continue"**. This saves the order, **generates the number** and enables the **"Send order for approval"** button. When sent, the order appears in the list as **"Awaiting approvals"**.

## Part 3 — Approval by steps

Once sent, the order follows the steps configured in the Approval Rule. In the current flow, the order is:

<DocTable
  headers={['Order', 'Step', 'Responsible group', 'When it applies']}
  rows={[
    ['1', 'ADM Approval', 'Sales ADM', 'Always.'],
    ['2', 'Credit Approval', 'Credit', 'Always.'],
    ['3', 'Collections – National', 'Collections', 'Only when the payment method is PIX or Card. Collections checks whether the customer has any overdue AR (accounts receivable).'],
  ]}
/>

At each approval, opening the order shows the **most recent update**. When the payment method is **not** PIX or Card, the **Collections – National** step does not apply and, after ADM and Credit, the order is already **released**.

<Callout type="info" title="The rule drives the flow">
The approval path comes from the Approval Rule. If the steps, the order or the conditions change in the rule, the flow changes with it — always check the current configuration.
</Callout>

## Quick summary

1. Prepare the queue without Ignition and configure the approval rule (once).
2. Create the new order and select the customer.
3. Fill in the required data and click "Save and Continue".
4. Send the order for approval ("Awaiting approvals").
5. Approve by ADM and Credit; National Collections applies only for PIX/Card.
6. After the applicable approvals, the order is released.

## Rules and cautions

- The **Ignition** option must be set so that the Ignition queue is **not** used in this flow.
- Approvals follow the **Approval Rule**: the mode (Parallel/Sequential), the active steps and the conditions determine the path.
- The **"Send order for approval"** button appears after **"Save and Continue"**.
- The **Collections – National** step only happens for **PIX or Card** and checks for **overdue AR**.
