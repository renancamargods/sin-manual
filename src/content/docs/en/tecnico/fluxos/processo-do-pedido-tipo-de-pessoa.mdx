## Overview

This is **Part 2** of the [Order Process](/en/tecnico/fluxos/processo-do-pedido). Here we detail the first major branch: the customer's **Person Type**. It determines the **currency**, whether the order follows the **domestic or international** path and which **review groups** the order goes through.

There are three person types: **Individual**, **Company** and **Foreign**. Individual and Company follow the **domestic path**; Foreign is treated as a **foreign trade customer** and follows the **international path**.

<Callout type="info" title="Person type comes from the customer">
You do not choose the person type on the order — it already comes from the selected **customer**. That is why the customer is the first and most decisive step of the process.
</Callout>

## Domestic or International: how it is decided

The order's **Domestic/International** field is set by the **address location**: if the **address country is Brazil**, the order is **Domestic**; otherwise, it is **International**. This comparison uses the **`IdPaisBrasil`** parameter (which tells the system which country is Brazil).

In practice, this aligns with the person type: **Individual/Company** (domestic) customers result in a **Domestic** order, and **Foreign** customers result in an **International** order. **Freight** follows: Foreign → **international freight**; the others → **domestic freight**.

<Callout type="atencao" title="The address decides">
Since the definition looks at the address country, keep the customer's address correct. A wrong address can classify the order as domestic/international incorrectly and affect currency, freight and review.
</Callout>

## Currency by person type

The currencies available for the order depend on the person type. This association is done on the **Currency × Person Type** screen (Orders module), which links each **currency** to one or more **person types**.

- It does not register the customer or the address — that is done in the Customers module.
- It does not define who approves — that comes from the Approval Rule (Order Approval flow).
