## Overview

The **Product Configuration in the Lounge** flow lets you configure a **Product (SKU)**, associating it with a **Family**, a **Group**, a **service Lounge** and a **Location** (Country, State and City). Based on this parameterization, when creating an order the system routes each item to the correct Lounge according to the customer’s location.

Each Lounge corresponds to a **Center in SAP**. Therefore, the configuration directly influences how many **Sales Orders** the order generates: items that go to different Centers generate separate Sales Orders, and items that go to the same Center are grouped into a single Sales Order.

The parameterization is done on the **Order Product Lounge Parameters** screen (Orders module) and its effect appears in the creation, approval and integration of orders with SAP.

## When to use this flow

- Register or look up a product’s parameterization by location and Lounge.
- Define which Lounge an item should go to according to the customer’s location.
- Understand why an order generated one or more Sales Orders in SAP.

## How to access

- Orders → Order Product Lounge Parameters
- Orders → Orders
- Approvals → New Approval Queue – Orders
- SAP → VA03 (checking the Sales Orders)

## Before you start

- Have access to the Orders module and the **Order Product Lounge Parameters** screen.
- Have a profile enabled in the approval flow (New Approval Queue – Orders), including the Credit level.
- Confirm that the products (SKUs) are registered and available for sale.
- Confirm that the customers have their location (City/State) defined.
- To check the Sales Orders, have access to SAP (transaction VA03).

## How the routing works

During order creation, for **each item** the system checks whether there is an **active** configuration whose location is compatible with the customer’s:

- **There is a compatible configuration** → the item goes to the **configured Lounge**.
- **There is no applicable configuration** → the item stays in the **order Lounge** (the one entered in the header).

<Callout type="info" title="Key concept: configured Lounge x order Lounge">
Parameterization by location takes precedence for items with a compatible configuration; the other items follow the order header Lounge. The number of Sales Orders generated equals the number of **distinct Centers** resulting from the item routing.
</Callout>

## Step by step of the process

### 1. Register the parameters

Orders module → **Order Product Lounge Parameters**. The screen has the **Search** area (filters), the **Search**, **+ New** and **Clear Filters** buttons, and the **Results** list.

Available search filters:

<DocTable
  headers={['Field', 'Required', 'Description']}
  rows={[
    ['Family', 'No', 'Searches by name or by the family code (x.x format).'],
    ['Group', 'No', 'Searches by name or by the group code (x.x.x format).'],
    ['Products', 'No', 'Searches by the product (SKU).'],
    ['Country', 'No', 'Filters by the country location.'],
    ['State', 'Conditional', 'Enabled only after filling in the Country.'],
    ['City', 'Conditional', 'Enabled only after filling in the State.'],
    ['Search Order', 'No', 'Filters by the search order/priority defined in the configuration.'],
  ]}
/>

To register, click **"+ New"**. The **"Product Configuration in the Lounge"** window opens with the fields:

<DocTable
  headers={['Field', 'Required', 'Description']}
  rows={[
    ['Code (SKU)', 'Yes', 'Product the configuration will be applied to.'],
    ['Search Order', 'No', 'Search order/priority of the configuration.'],
    ['Country', 'Conditional', 'Country location of the configuration.'],
    ['State', 'Conditional', 'Enabled only if the Country is filled in.'],
    ['City', 'Conditional', 'Enabled only if the State is filled in.'],
    ['Lounge Name', 'Yes', 'Service Lounge the item will be routed to (corresponds to a Center in SAP).'],
    ['Status', 'Yes', 'Status of the parameter: Active or Inactive.'],
  ]}
/>

At the end, use **"Save"** or **"Save and Continue"**.

<Callout type="info" title="What the configuration associates">
Each configuration associates the **Product (SKU)** with a **Family**, a **Group**, a **Lounge** and a **Location** (Country, State and City). It is this combination that defines which Lounge the item will be routed to.
</Callout>

<Callout type="dica" title="Select ALL by level">
In the Country, State and City fields there is an "ALL" checkbox. When checked, it selects all items at that level (all countries, all states or all cities), broadening the scope of the configuration.
</Callout>

### 2. Create the order

Orders module → **Orders**. Create the order normally, with the customer and the items. On creation, the system routes each item according to the parameterization and the customer’s location. The orders get the status **"Awaiting Approvals"**.

### 3. Approve the order

Approvals module → **New Approval Queue – Orders**. Orders with the block reason **"Credit"** are handled in the **"Orders to Release"** tab. Approve the order through the corresponding level.

### 4. Confirm the integration

Back in **Orders**, the approved order moves to the **"Integrated"** status and receives the **SAP Order** number. In the status history ("Status Updates"), each integration corresponds to a **Sales Order** — an order can have more than one record, one per Center.

### 5. Check in SAP (VA03)

In SAP, in transaction **VA03**, search by the order number and check the **Sales Orders**, their **items** and the **Centers** corresponding to each Lounge.

## Rules and cautions

- The number of Sales Orders depends on the diversity of Centers in the routing; changing the parameterization changes the number of Sales Orders.
- The location hierarchy (Country → State → City) determines compatibility; check the precedence of more specific configurations (with City).
- Only **Active** configurations are considered in the routing.
- The exact behavior of the **Search Order** (tie-breaking between configurations) is a point to validate with the responsible team.
