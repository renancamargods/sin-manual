## Overview

**TDC — Exchange, Return and Cancellation** is the process that handles the return of already-invoiced items. It starts with a **triage** (the **TDC Order**), where you record the items the customer returns and/or the items to be sent as an exchange. From that triage, the system **generates the matching orders** — **return**, **exchange** or **consignment** — and computes the value **difference** (credit or debit) for the customer.

This flow is the natural continuation of [Order Invoicing and Serial Movement](/en/tecnico/fluxos/faturamento-e-movimento-serial): an order can only enter return or exchange after it has been invoiced and its serial movement recorded.

## When to use this flow

- Record the **return** of items from an already-issued invoice.
- Perform an **exchange** of items (return some and send others in their place).
- Handle a **consignment return**.
- **Cancel** a triage (protocol) that will not be completed.

## Step 1 — Open the triage (TDC Order)

The triage is the header of the process. When you open a new **TDC Order**, you record:

- **Protocol** — the triage identifier (generated by the system).
- **Customer(s)** tied to the operation.
- **Lounge/Center** and reference **Price List**.
- **Ticket number (FreshDesk)** — link to the support case that originated the return.
- **Notes** and the initial status **"Triage started"**.

<Callout type="info" title="A protocol can have more than one customer">
The triage supports more than one customer in the same operation. The system warns when there is **"More than one Customer in the Return"** so the computation is done correctly.
</Callout>

## Step 2 — Return items

The items coming back are added to the triage in two ways:

- **By Invoice:** select the source invoice and pick, among its items, the ones to be returned.
- **By scanning (DataMatrix):** read each item's **DataMatrix**. If not found, the system shows **"DataMatrix not found"**.

Each scanned item can be removed with the confirmation **"Confirm deleting the scanned item for Return?"**. The system also performs a **real-time stock check** and validates the **Return Authorization**.

## Step 3 — Exchange items

When the operation is an **exchange**, besides the returned items you add the **items to be sent** — through the **"Item Troca"** (Exchange Item) grid or the **"Digitação Rápida Item Troca"** (Quick Entry Exchange Item).

Before adding an exchange item, the system requires (real validation):

- A **Customer** tied to the item.
- An **Operation** (Smart Operation) selected for the item.
- A **Quantity** filled in and **greater than or equal to 1**.
- A **Product** selected — needed to load the **table price**.
- The **Item type** (Sale or Bonus — `TIpoDeItemPedidoTDC`).

With the items loaded, the system computes the **unit price**, the **suggested discount for the exchange items**, the customer's **Available Credit** and the **"General Difference"** — the credit or debit balance of the operation.

## Step 4 — Generate the order

With the return and/or exchange assembled, use **"Generate Order"**. Depending on the case, the triage generates:

<DocTable
  headers={['Value', 'Status generated', 'Meaning']}
  rows={[
    ['1', 'Return order created', 'Generated the return order for the items.'],
    ['2', 'Exchange order created', 'Generated the exchange order (sending the new items).'],
    ['3', 'Early exchange order created', 'Generated the early exchange (sending before the return).'],
    ['5', 'Consignment order created', 'Generated the consignment order.'],
  ]}
/>

The generated orders stay linked to the triage. While nothing is generated, the system shows **"No order generated yet from this"** triage.

## Step 5 — Tracking, completion and cancellation

- Each change is recorded in the history (**"Detailed Status Information"**) and in the TDC Order **Logs**.
- Once the operation is done, the triage moves to **"Triage finished"**.
- A triage that will not be completed can be **canceled** (status **"Canceled"**), with confirmation by protocol.

## Relationship with other processes

- **Invoicing and Serial Movement:** the return starts from an invoiced document; the item must have a **serial movement** — see [Order Invoicing and Serial Movement](/en/tecnico/fluxos/faturamento-e-movimento-serial).
- **DataMatrix Analysis / Return Analysis:** supports checking the returning items by DataMatrix reading.
- **Value Mapping:** the codes for `TipoOperacaoTDC`, `StatusDePedidoTDC` and `TIpoDeItemPedidoTDC` are in [Database → Value Mapping](/en/tecnico/banco-de-dados/de-para).

## Common problems

- **"DataMatrix not found" when scanning the return:** confirm the item was invoiced and has a serial movement (see the Invoicing flow).
- **"An order was already generated for the selected invoice":** that invoice already produced an order in the triage; check the order shown.
- **Cannot add an exchange item:** check the customer, operation, quantity (≥ 1), product (to load the table price) and item type.
- **"More than one Customer in the Return":** review the triage customers so credit/debit is computed on the right customer.
