## Overview

When an order is submitted, **before** it enters the approval queues (Sales Admin, Credit, Collections), the system runs an **automatic analysis**. This analysis decides three things: whether the order can **integrate straight to SAP**, whether it must stop at some **approval area**, and **why**.

The analysis has three tracks, run in sequence:

1. **Sales Admin** — 12 commercial-policy validations that generate **blocking reasons**.
2. **Credit Engine** — a **decision tree** that approves the order or routes it to the **Credit Desk** (manual review).
3. **Collections** — checks whether the customer is **overdue / a debtor**.

<Callout type="info" title="This page is the 'engine', not the queue">
The **[Order Approval - Without Ignition](/en/tecnico/fluxos/aprovacao-de-pedidos-sem-ignition)** flow shows **the queues** (who approves and in what order). This page shows what the system decides **on its own, before the queues** — including when the order is released without anyone acting on it.
</Callout>

## When to use this flow

- Understand **why** an order was approved automatically, stopped at Credit, or stopped at Sales Admin.
- Explain to the user the **blocking reason** shown on the order.
- Investigate an order that landed on the **Credit Desk** (manual review).

## How to access

- **Orders** module → **Order** → view the **Blocking Reasons** and the order **analysis log**.
- The limit settings are in the **Administrator** module (Parameters / Feature Control).

## Track 1 — Sales Admin (12 validations)

The system runs 12 validations **in order**. Each one that fails generates a **blocking reason** and the order stops at the **Sales Admin** area (status "Administrative Review"). Before it starts, the order's previous blocking reasons are **cleared** (the analysis restarts from scratch).

<Callout type="dica" title="Key Account (KA) has an exception">
If there is a Sales Admin block but the order is a **Key Account (KA)**, it does **not** stop at Sales Admin — it goes straight to Credit analysis. The full list of reasons is in **[Blocking Reasons](/en/tecnico/referencia-motivos-de-bloqueio)**.
</Callout>

## Track 2 — Credit Engine (decision tree)

The Credit Engine is an **ordered tree**: the **first** condition met **interrupts** the analysis and sets the order's destination. The order is exactly this:

  headers={['#', 'Step', 'Condition', 'Result']}
  rows={[
    ['0', 'Foreign Customer', 'Customer is of type Foreign.', 'Skips credit analysis (no credit block).'],
    ['0', 'Not in the DW', 'Customer not found in the DW base (Score/Rating).', 'Credit Desk (manual review).'],
    ['0', 'No payment terms', 'Payment method/terms not identified.', 'Credit Desk.'],
    ['1', 'Blacklist', 'Customer is on the blacklist.', 'Interrupts; follows the status suggested by the validation.'],
    ['2', 'Bank Deposit', 'Payment method is bank deposit.', 'Interrupts; suggested status.'],
    ['3', 'Card / PIX', 'Eligible card/PIX payment method.', 'Automatic approval by payment terms.'],
    ['4', 'PFCQ Bonus', 'ERP order is a PFCQ bonus.', 'Interrupts; may be an OPL operation.'],
    ['5', 'OPL Shipment', 'Operation is an OPL shipment.', 'Interrupts; OPL operation integrates automatically.'],
    ['6', 'Mixed Payment', 'Order combines more than one payment method.', 'Interrupts; handles mixed payments.'],
    ['7', 'Serasa [Configurable]', 'Serasa flow enabled AND order value above the Serasa value.', 'Queries Serasa; if refused, goes to Credit Desk.'],
    ['8', 'CAR / Delinquency', 'CAR (accounts receivable) above tolerance.', 'Credit Desk ("CAR above limit").'],
    ['9', 'Order Value', 'Value above the allowed limit.', 'Interrupts; suggested status.'],
    ['✓', 'Approved', 'Passed all steps above.', 'Automatically approved by the engine, per current policy.'],
  ]}
/>

<Callout type="info" title="Serasa — when it is queried">
Serasa is **only** queried when the Serasa flow parameter is **on** and the **order value** is greater than the configured value. Below that value, it is not queried. If Serasa **refuses**, the order is routed to manual review (Credit Desk).
</Callout>

## Track 3 — Collections

The **Collections** area checks whether the customer is **overdue / a debtor** ("Delinquent Customer" rule). If so, the order requires Collections approval. In practice, the **Collections – National** step is the one that enters for **PIX or Card** payments and checks **overdue CAR** (see the queue approval flow).

/>

<Callout type="dica" title="How the order value is calculated">
Value = (sum of **Sale + Campaign + Consignment** items + **Freight**) − (**total discount %** × sum of items). **Bonus** items are summed separately and do **not** enter the base value. This is the value used by the **Minimum Value**, **Serasa** and **Order Value** rules.
</Callout>
