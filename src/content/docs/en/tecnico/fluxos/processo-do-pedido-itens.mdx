## Overview

This is **Part 3** of the [Order Process](/en/tecnico/fluxos/processo-do-pedido). Here we detail the order **items**: each item is a **product** with an **Item Type**, a **quantity** and a **price**. The **Table Price** comes from the **Price List**, and **discounts** (by item or by policy) may apply on top of it.

The item type defines the product's role in the order (normal sale, bonus, campaign, etc.) and, in some cases, activates its own rules — for example, a **bonus** item is only accepted with an **allowed Smart Operation**.

## When to use

- Understand which item types exist and what each one means.
- Know where the price comes from and how the discount is applied.
- Diagnose why an item blocked the order submission.

## Item validation rules (on submission)

Beyond the fields above, on submitting the order the system validates the set of items:

<DocTable
  headers={['Rule', 'What the system checks', 'If it fails']}
  rows={[
    ['Existing product', 'Each item must point to a valid/findable product.', 'Blocks submission, indicating the product and the item position.'],
    ['No duplication', 'The same product with the same item type cannot be repeated.', 'Blocks submission, pointing to the duplicate item (product and type).'],
    ['Bonus x Smart Operation', 'If the order has only bonus items, it requires an allowed Smart Operation (system parameter).', 'Blocks submission until a valid operation is indicated.'],
    ['Campaign x policy value', 'Campaign items must match the value required by the policy (value × quantity).', 'Blocks if the submitted value is greater or lower than specified in the policy.'],
  ]}
/>

<Callout type="atencao" title="Bonus requires an allowed operation">
**Bonus** items only pass when there is an **allowed Smart Operation** for bonus. The list of accepted operations comes from a **system parameter** (`IdsOperacoesInteligentesDeBonificacao`). See Part 6 - Permissions & Parameters.
</Callout>

## What this stretch does not do

- It does not register products or price lists — it only uses the items in the order.
- It does not define the campaign/policy rules themselves — that is in Part 5.
