## Overview

The **SAP S/4HANA** integration sends the records and documents created in the CRM to SAP — **customer**, **order**, **delivery** and **invoice**. It is a **configuration-driven step engine**: each document type has a **flow** with one or more ordered **steps**, and each step knows which operation to run against SAP. So adjusting the integration is, most of the time, **changing configuration** — not code.

This page is the overview (the "how it works"). The step-by-step of each flow is in [SAP Integration — The four flows](/en/tecnico/fluxos/integracao-sap-os-quatro-fluxos).

## The pieces of the integration

- **Flow** — the process for a document type (e.g., Business Partner, Sales Order). Configured in **Integration Flows**.
- **Step** — each ordered step within a flow. A flow can have one or several steps.
- **Step type** — defines which **executor** the step uses and against which SAP service. Configured in **Step Type**.
- **Connection** — the SAP environment address and credentials. Configured in **SAP Integration Configuration**.
- **Monitoring** — tracks each integration and step (status, attempts, logs). The **SAP Integration Monitoring** screen.

<Callout type="info" title="Where to configure">
The screens are in the **Integrador** module: Integration Flows, Step Type, SAP Integration Configuration and SAP Integration Monitoring.
</Callout>

<Callout type="cuidado" title="Awaiting manual action">
An integration reaches **"Awaiting manual action"** in three ways: a **business precondition** not met (e.g., a required field missing in the CRM), the **retries exhausted**, or when a step's result **requires human checking** (e.g., the document was created in SAP but the CRM could not identify its number).
</Callout>

## How a step is executed (summary)

1. The step enters **"In progress"**.
2. **Idempotency:** if that step already created the document in SAP before, the engine **does not repeat** the call — it only re-records it in the CRM. This avoids a duplicate document on reprocessing.
3. The **business rule** reads the CRM and assembles what will be sent.
4. The **executor** performs the SAP operation and interprets the response.
5. On a **temporary failure**, the engine **reschedules** with progressive backoff, up to a limit; definitive errors go straight to manual action.
6. Each call becomes a **log** line (date, status, duration) for monitoring.
