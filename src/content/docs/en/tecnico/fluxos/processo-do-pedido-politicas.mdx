## Overview

This is **Part 5** of the [Order Process](/en/tecnico/fluxos/processo-do-pedido). The **purchase policies** are the commercial rules that act on the order: the **Commercial Policy** and the **Campaigns** define prices, discounts and values required per item; the **Sales Restriction** limits **what can be sold** to each segment.

These rules come in both during **building** (item price/discount) and during the order **review** (the commercial area checks for restriction/exception).

## When to use

- Understand why an item came with a certain price/discount.
- Know why a sale was limited by restriction.
- Diagnose why submission blocked due to a campaign value divergence.

## Commercial Policy

The **Commercial Policy** is a commercial rule with validity and segmentation. It can adjust the price/discount and requires values per item.

<Callout type="atencao" title="Per-item value validation">
Items linked to a **campaign/policy** have the value checked on submission: the system compares the **item(s) value × quantity** with the value specified in the policy and **blocks** submission if the submitted value is **greater or lower** than required. See Part 3 - Items.
</Callout>

## Campaigns

The **Campaigns** (registered in Campaign Parameter, in the Policies module) define campaign items applied to the order. An item of type **Campaign** carries the link with the campaign/policy and is checked by the same value rule above.

## Sales Restriction

The **Sales Restriction** limits which products can be sold to certain segments. It is segmented by several criteria:

  headers={['Restriction segmentation', 'What it limits']}

    ['Product Group', 'Restricts by product group.'],
    ['User Group', 'Restricts by user group.'],
  ]}
/>

<Callout type="info" title="The restriction comes in at review">
The Sales Restriction is checked in the order **review**: the **Sales Administrative** area verifies whether the order contains an **exception product** (restricted) for that segment. See the <em>Order Approval - Without Ignition</em> flow.
</Callout>

## What this stretch does not do

- It does not register the policies, campaigns or restrictions — that is done in the Policies module.
- It does not define who approves — the restriction/exception is checked in the review (Order Approval).
