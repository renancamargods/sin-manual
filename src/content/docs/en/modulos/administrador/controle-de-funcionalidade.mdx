## Overview

The **Feature Control** screen manages system features through an **Identifier Key**. Each feature can be **Enabled** or not, has a **Value Type** (Boolean, Text, Number or Json) and a corresponding **Value**, plus a **Name** and **Description**. It is the system's *feature flags* mechanism.

<Callout type="cuidado" title="Technical configuration">
Changing a feature changes the system's behavior. Only make changes when you know the key and the expected effect, preferably with support from the technical team.
</Callout>

## When to use this screen

- Register a new feature controlled by a key.
- Enable or disable a feature.
- Adjust a feature's value.

## How to access

Administrator → Feature Control

## Before you start

- Have the feature's **Identifier Key**.
- Know the **Value Type** (Boolean, Text, Number or Json) and the correct **Value**.

### Feature catalog (the ones the system reads today)

These are the features the system **actually reads** to decide behavior (each one by a **Feature Identifier Key**). What turns it on/off is the **Enabled** column; some also use the **Value** field (e.g., a configuration JSON). The current state (on/off) is what shows on the screen itself, so it is not repeated here.

<Callout type="info" title="Enabled × Value">
Most keys are a **switch** (**Enabled** = Yes/No). Some, like **Pedidos.SinSolution.Listagem.Completa**, also need the **Value** field filled (a configuration JSON) — if the Value is empty or invalid, the feature has no effect even when Enabled.
</Callout>

<Callout type="atencao" title="A key may exist with no effect">
The screen lets you register **any** key. Only the keys the system actually reads (the ones in the catalog above) change behavior — a new key only takes effect once the code is adjusted to read it. So creating a stray key does not turn on any feature by itself.
</Callout>

<Callout type="info" title="How the key turns Ignition on/off">
The **Fila.Clientes.SemIgnition** and **Fila.Pedidos.SemIgnition** keys decide which **approval queue** the system uses:

- **Enabled = Yes (Active)** → uses the **new queue WITHOUT Ignition** (the faster path, described in [Customer Registration WITHOUT Ignition](/en/tecnico/fluxos/cadastro-clientes-sem-ignition) and [Order Approval WITHOUT Ignition](/en/tecnico/fluxos/aprovacao-de-pedidos-sem-ignition)).
- **Enabled = No (Inactive)** → goes back to the **queue WITH Ignition** (the previous path, with Ignition — see [Customer Registration WITH Ignition](/en/tecnico/fluxos/criacao-de-cliente)).

Today, in Homologation, both keys are **Enabled (Active)** — that is, customers and orders follow the queue **WITHOUT Ignition**.
</Callout>

## Main flows

1. **Search** — enter the **"Feature Identifier Key"** and click **"Search"**.
2. **Register** — click **"+ New"**, enter **Key**, **Name**, **Description**, the **Value Type** and the **Value**, set **Enabled** and the **System Status** and click **"Save"** (or **"Save and Continue"**).
3. **Edit / enable** — click the **Edit** icon on the row, adjust **Enabled** or the **Value** and click **"Save"**.
4. **Delete** — click the **Delete** icon on the row.
