## Overview

The **Approval Rule** screen defines who should approve a request — such as an order or a contract — and under which conditions that approval is required. Each rule is applied to a previously registered approval entity.

## When to use this screen

- Register a new approval rule.
- Look up the rules already configured for an entity.
- Change the approver or condition of an existing rule.

## How to access

Approvals → Approval Rule

## Before you start

- Confirm which approval entity the rule will use.
- Define in advance who the responsible approvers will be.
- Check whether a similar rule is not already configured.

## Main flows

1. **Register a new rule** — select the entity, define the condition and the approver.
2. **Look up rules** — use the search to find rules by entity.
3. **Change a rule** — update the condition or approver as needed.
4. **Inactivate a rule** — disable a rule that should no longer be applied.

## Relationships with other records or processes

This screen depends on an entity registered in Approval Entity. The rules configured here directly affect the progress of orders, contracts and other requests that require approval.

<Callout type="cuidado" title="Immediate effect">
Changes to an approval rule apply to new requests from the moment they are saved.
</Callout>

## Important parameters and behaviors

- The rule must be active to be applied to new requests.
- Changes do not affect requests already in progress in the approval flow.
- More than one rule can be applied to the same entity, depending on the configured condition.

## Rules and cautions

- Review the rule condition before saving, to avoid unnecessary or missing approvals.
- Avoid registering conflicting rules for the same entity.
- Prefer to inactivate rather than delete a rule that has already been used.
- Check your permissions before changing a rule in use.
